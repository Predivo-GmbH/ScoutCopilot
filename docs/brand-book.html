08 / Design Guidelines

Do's & Don'ts

These rules prevent generic AI aesthetics and maintain the Analytical Architect identity.

Do

  • Use JetBrains Mono for all numbers and statistics
  • Use 1px border hairlines to define containers
  • Use tonal stepping for depth hierarchy
  • Keep corners tight: 6px default, 2px for badges
  • Use asymmetric borders (2-3 sides) for editorial feel
  • Make data views information-dense
  • Use emerald/amber as functional signal colors
  • Respect prefers-reduced-motion for all animations

Don't

  • Use gradient backgrounds on sections or cards
  • Use stock photography or generic imagery
  • Use pill-shaped buttons or badges (rounded-full)
  • Add decorative icons without functional purpose
  • Use pastel color washes (baby blue, lavender, mint)
  • Add AI sparkles, magic wands, or "powered by AI" badges
  • Use drop shadows to define containers
  • Use any font other than Inter or JetBrains Mono

Border Philosophy

Correct

Asymmetric borders (left + bottom) create editorial framing

Avoid

Heavy shadows + borders on all sides feels "boxy"

Color Usage

Correct

  • Blue for primary actions and active states
  • Emerald for success, positive metrics, "green flags"
  • Amber for warnings, alerts, attention needed
  • Flat, confident color fills

Avoid

  • Gradients for visual interest
  • Colors without semantic meaning
  • Multiple accent colors competing for attention
  • Pure black (#000000) backgrounds
